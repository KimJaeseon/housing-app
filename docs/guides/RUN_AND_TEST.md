# 직접 실행하고 테스트하기

최신 안내: 2026-09-17. Windows / 현재 프로젝트 환경 기준.

## 1. PC에서 실제 앱 실행

PowerShell 창 1 — 서버:

```powershell
cd C:\data\menual\housing-app-guidelines
.\.venv\Scripts\python.exe -m backend.serve_lh --start 2026.08.01 --end 2026.09.16
```

저장된 승인키를 자동으로 읽는다. 8000 포트가 사용 중이면 기존 개발 서버 창에서 Ctrl+C로 종료한 뒤 실행한다.

PowerShell 창 2 — 앱:

```powershell
cd C:\data\menual\housing-app-guidelines\frontend
& 'C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\bin\fallback\pnpm.cmd' web
```

브라우저에서 http://localhost:8081 을 연다. 위 경로 대신 pnpm이 설치된 환경에서는 `pnpm web`을 사용할 수 있다. 종료할 때 두 창에서 각각 Ctrl+C를 누른다. 자동검사는 별도 서버를 종료한 상태에서 실행한다.

기간은 공고의 게시일 조회 범위다. 예시는 이번 검증을 재현하는 기간이며 현재 모집 중 공고 전체를 보장하지 않는다. 날짜를 바꿀 때는 서버를 종료하고 `--start`와 `--end`를 바꿔 재실행한다. 날짜를 지정하지 않은 자동 전수 조사는 아직 구현하지 않았다.

## 2. 지금 직접 확인할 화면

| 순서 | 사용자 동작 | 기대 결과 |

| 2 | 이번 조회 범위 확인 | 입력한 게시일 기간, 페이지·건수, 미지원 기관과 원문 검증 제한을 읽을 수 있다. |
| 3 | 확인된 공고 탭 | 검증기가 미완성이라 0건이다. 이를 서울 전체 공고 없음이라고 안내하지 않는다. |
| 4 | 마감·취소로 제외된 공고 탭 | 검증 당시 예시 기간에서는 서울번동3 원공고·정정공고 2건이 표시됐다. 실시간 자료 변경으로 결과는 달라질 수 있다. |
| 5 | 정정공고 상세 보기 | 목록 상태·게시일·마감일과 확인 시점을 표시한다. 접수 회차·시간·금액·자격은 미확인으로 표시한다. |
| 6 | 공식 원문 열기, 앱으로 복귀 | LH 공식 상세로 이동한다. 외부 브라우저에서 돌아온 뒤 상세와 이전 목록을 계속 볼 수 있다. |
| 7 | 검색 결과로 돌아가기 | 방금 열었던 공고의 상세 버튼으로 키보드 초점이 돌아간다. |

| 9 | 서버 종료 후 앱에서 다시 검색 | 연결 실패와 재시도 안내가 나온다. 공고 없음으로 표시하지 않는다. |

실제 기간에 접수 중 후보가 없으면 확인 필요 목록이 비어 있을 수 있다. 해당 화면과 오류·페이지 제한 상태는 합성 자료 기반 자동검사로도 확인했다. 공고 건수를 맞추려고 날짜나 상태를 임의로 변조하지 않는다.

## 4. 직접 도와주실 수 있는 실기 검증

웹 자동검사로 대체할 수 없는 항목이다. 시험 기기의 기종·OS·화면 읽기 설정과 함께 결과를 기록하면 된다.

- Android TalkBack / iPhone VoiceOver를 켜고, 화면을 보지 않은 상태로 지역 입력 → 검색 → 탭 전환 → 상세 → 공식 원문 → 복귀를 수행한다.
- 최대 글자 크기에서 검색 버튼·공고 제목·오류 안내가 잘리거나 겹치지 않는지 확인한다.
- 조사 중·실패·마감·확인 필요 상태가 음성으로 구분되는지 확인한다.
- 상세에서 돌아왔을 때 읽던 공고로 초점이 돌아오는지 확인한다.
- 문제가 생기면 `기기 / 진행 순서 / 기대한 동작 / 실제 동작` 네 가지를 알려준다. 승인키나 개인정보는 포함하지 않는다.

휴대폰 Expo 실행 준비:

1. PC와 휴대폰을 같은 개발용 네트워크에 연결하고 PC의 로컬 IP 주소를 확인한다.
2. 서버를 `--host 0.0.0.0` 옵션과 함께 실행한다. 이 설정은 같은 네트워크의 기기 연결용이며 공개 인터넷 배포가 아니다.
3. 앱 실행 PowerShell에서 `$env:EXPO_PUBLIC_API_URL='http://PC의로컬IP:8000'`을 설정하고 pnpm start를 실행한다. 이 변수에는 서버 주소만 넣고 승인키를 넣지 않는다.
4. Expo에 표시되는 안내대로 기기에서 연다. 현재 Expo SDK와 기기 앱의 호환성, 방화벽 연결은 기기에서 확인해야 하며 이번에는 미검증이다.
5. 네이티브 앱이 열리지 않으면 우선 휴대폰 브라우저 테스트와 네이티브 VoiceOver/TalkBack 테스트를 구분해서 기록한다. 웹 테스트 성공을 네이티브 통과로 처리하지 않는다.

## 6. 주택형별 공급정보 조회 (2026-09-17 추가)

서버를 기존 실행 명령으로 재시작하면 목록과 공급정보 연결이 함께 활성화된다. 기존에 저장한 암호화 키 파일을 재사용한다. 키를 앱, 채팅, 소스코드에 붙여 넣지 않는다.

1. 서울 공고 조회 → 확인 필요 또는 마감·취소로 제외된 공고 → 상세 보기로 이동한다.
2. 상세 아래의 **공급정보 조회**를 누른다. 요청한 공고 한 건만 조회한다.
3. 지원 범위는 공급정보 유형 061/062/063, 임대주택 06, 연결시스템 03이다. 다른 유형은 미지원 안내가 나온다.
4. 성공하면 주택형별 전용면적·세대수·보증금·월 임대료, 확인 시점과 근거 위치를 읽는다. 숫자라도 단위가 확인되지 않으면 미확인이다. ‘공고문 참조’를 0원으로 표시하지 않는다.
5. ‘공급정보 서비스의 활용승인을 확인해 주세요’가 나오면 공공데이터포털의 [한국토지주택공사 분양임대공고별 공급정보 조회 서비스](https://www.data.go.kr/data/15056765/openapi.do) 활용신청·승인 상태를 확인한다. 목록 API와 별도 서비스다. 기존 점검에서 HTTP 403 / API_KEY_NOT_REGISTERED가 발생했으며 성공 실데이터는 아직 확인하지 못했다.
6. 승인 반영 후 **검색 결과로 돌아가기 → 다시 조사하기 → 공고 상세 → 공급정보 조회** 순서로 새 검색에서 재확인한다. 동일 검색·공고의 공급 요청은 결과를 재사용하므로 조회 버튼 연타로 외부 API를 반복 호출하지 않는다. 네트워크 응답 유실은 같은 검색에서 재조회할 수 있다.
7. 조회 중 뒤로 가기 후 다른 공고를 열어도 이전 결과가 섞이지 않는지 확인한다.

추가 수동 확인: iOS VoiceOver와 Android TalkBack 각각에서 조회 버튼 이름·비활성 상태·완료/오류 안내를 읽고, 결과가 초점을 빼앗지 않는지 확인한다. 최대 글자 크기에서 주택형·금액 단위·미확인 사유가 잘리지 않아야 한다. 실제 모바일 기기 검사는 아직 미실행이다.

이 단계는 공급정보 API 연결이다. 접수 회차·신청 자격·첨부 공고문·최종 정정 관계 검증은 다음 단계이며, 공급정보를 받았다는 이유로 ‘확인 완료’ 공고로 승격하지 않는다.


추가 상태 (2026-09-17): 사용자가 공급정보 API 활용신청 완료를 알렸다. 위의 이전 403 기록은 신청 전 점검 결과다. 신청 이후 승인 반영 및 실제 성공 응답은 아직 재확인하지 않았다. 키 재전달 없이 기존 암호화 파일로 새 검색에서 확인한다.
