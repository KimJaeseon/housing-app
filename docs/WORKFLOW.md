# 병렬 작업 흐름

이 파일은 하네스 실행 계약이다. 문서 자체가 에이전트를 실행하지는 않는다. 실행 도구가 있는 환경에서 총괄이 작업을 배정하고 상태를 추적한다.

## 단계
1. 총괄: 명세 고정, 작업 ID·담당·파일 소유권·공통 인터페이스 초안 배정.
2. 병렬 설계: 청약 조사·검증, 모바일·접근성, 서버·데이터가 각 전문 지침과 설계를 작성. 같은 파일을 동시에 수정하지 않는다.
3. 계약 통합: 검증 필수 항목과 출처 접근 방식을 확정하고 데이터·화면·오류 상태를 맞춘다.
4. 병렬 구현: 출처 어댑터, 모바일 화면, 서버·계정 모듈을 소유권에 따라 구현. 의존하는 인터페이스는 확정된 계약을 사용한다.
5. 품질 검토: 결과와 실제 근거를 읽어 정확성·접근성·권한·실패 복구를 검수.
6. 수정·통합: 실패 항목만 재배정. 최종 검수와 실행 안내를 제공.

## 작업 메시지 형식
각 배정에 작업 ID, 역할, 목표, 입력 파일, 수정 허용 파일, 의존 작업, 산출물, 완료 기준, 시간 예산을 포함한다. 각 결과에는 상태, 수정 파일, 검증 증거, 가정, 미해결 문제, 인계 요청을 포함한다.

## 하네스 운영 기본값
- 상태: 대기 → 실행 중 → 검토 대기 → 완료. 실패·차단은 별도 상태로 관리.
- 동시 실행 수: 도구가 허용하는 범위 안에서 기본 전문 역할 3개. 슬롯이 부족하면 대기열로 진행.
- 시간 예산: 배정 시 작업 크기에 맞춰 정한다. 초과 시 상태·부분 결과를 수집하고 원인을 진단한다.
- 일시적 도구 오류: 원인을 확인한 후 최대 2회 재시도. 영구 오류·권한 오류를 반복 호출하지 않는다.
- 검토 수정: 기본 최대 2회. 이후 차단 문제는 근거와 해결 선택지를 보고하고 완료로 표시하지 않는다.
- 사용자 변경: 영향을 받는 작업을 중지·재배정하고 명세 버전을 갱신한다. 무관한 완료 작업은 유지.

## 앱 내 검색 실행 흐름
지역 정규화 → 공식 출처별 조사 작업 병렬 실행 → 원문·정정 확인 → 필드 검증·중복 통합 → 확인된 결과 점진 표시 → 조사 종료 또는 일부 실패 표시.
이 검색 병렬 처리와 개발 에이전트 병렬 처리는 별개다. 출처별 호출 제한·시간 제한·취소·재시도는 서버 역할 계약을 적용한다.

## 인계 및 종료 조건
조사 역할은 출처별 접근 가능성·근거 필드·검증 규칙을 서버로, 서버는 응답·오류 계약을 모바일로 전달한다. 품질 검토자는 세 역할 결과가 준비된 뒤 통합 검수를 시작한다. CHECKLIST.md 필수 항목 증거가 갖춰지고 차단 문제가 해소되어야 시험 운영 완료다.
