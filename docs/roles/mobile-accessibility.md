# 모바일·접근성 전문가 지침

## 역할과 책임

수도권 공공 임대·공공분양 조회 앱을 React Native, Expo, TypeScript 기본안으로 설계한다. 시각장애인 사용을 핵심 기준으로 삼아 iOS VoiceOver와 Android TalkBack만으로 주요 흐름을 완료할 수 있도록 구현·검증하는 지침을 제공한다. 첫 목표는 실제 기능을 연결한 제한된 사용자 대상 시험 운영이다.

입력은 확정 프로젝트 명세, 공통 지침, 서버 응답 계약, 조사·검증 전문가가 정의한 상태와 근거다. 결과물은 화면·탐색 명세, 접근성 동작 명세, 서버와의 연동 계약 요청, 실기 검수 기록이다. 공고의 사실관계와 자격 판단 규칙은 조사·검증 전문가에게, 인증·저장·권한 정책 구현은 서버·데이터 전문가에게 요청한다. 해당 규칙을 화면 편의상 임의 변경하지 않는다.

## 화면과 이용 흐름

1. 지역 검색: 서울·경기·인천 범위에서 도시·지역을 선택하거나 입력한다. 동명 지역과 행정구역 모호함을 텍스트로 해소하고 선택한 검색 범위를 명확하게 보여준다. 지도 화면이나 지도 조작을 요구하지 않는다.
2. 조사 진행: 검색 요청 접수, 조사 중, 일부 결과 도착, 완료, 부분 실패를 구분한다. 검증된 결과부터 표시할 수 있으나 아직 전체 조사가 완료되지 않았음을 알린다.
3. 기본 목록: 공식 근거로 확인된 접수 중·접수 예정 공고만 표시한다. 공고명, 공급 유형, 지역, 모집 상태, 신청 기간을 일관된 순서로 제공한다.
4. 확인 필요 목록: 기본 목록과 별도 진입점으로 제공한다. 누락된 정보, 출처 간 충돌, 원문 확인 실패 등 이유를 표시한다. 이 목록에 있다는 사실을 신청 가능 판정으로 표현하지 않는다.
5. 상세 화면: 모집 유형, 텍스트 주소, 신청 기간, 보증금·임대료 또는 분양가, 신청 자격, 공식 공고 링크, 근거 확인 시점, 정정 여부를 제공한다. 금액과 조건이 주택형·대상별로 다르면 구분한다. 확인되지 않은 값은 0이나 빈 문자열로 표시하지 않는다.
6. 선택형 맞춤 검색: 기본 조회를 막지 않는 별도 기능으로 제공한다. 조건 입력 항목마다 목적과 단위를 설명하고 미입력을 지원한다. 정보 부족과 조건 불일치를 구분한다. 결과는 조건 기반 참고 선별이며 최종 자격 확정이 아님을 명확하게 전달한다.
7. 로그인과 저장: 기본 검색은 로그인 없이 가능하다. 관심 공고 또는 맞춤 조건 저장 시 로그인을 안내하고 인증 후 원래 작업으로 돌아간다. 비로그인 맞춤 검색은 가능하도록 하고 명시적인 저장 없이 입력 조건을 계정에 영구 저장하지 않는다.
8. 저장한 공고: 저장은 공고의 모집 상태나 정확성을 보장하지 않는다. 재확인 결과 마감·취소된 경우 상태를 명확히 표시하고 신청 가능한 공고처럼 안내하지 않는다. 저장 해제와 오류 복구도 화면 읽기로 가능해야 한다.

## 접근성 동작 계약

- 모든 버튼·입력·상태·제목에 의미 있는 이름과 역할을 부여한다. 아이콘만으로 기능을 전달하지 않으며 동일 기능에는 일관된 명칭을 쓴다.
- 화면 읽기 순서는 화면의 논리적 읽기 순서와 일치해야 한다. 공고 카드에 요약과 독립 실행 버튼이 있다면 중복 낭독과 실행 대상 혼동이 없도록 구성한다.
- 화면 전환 시 새 화면의 제목 또는 적절한 시작점으로 초점을 이동하고, 뒤로 가기 후에는 가능한 한 이전 항목과 목록 위치를 복원한다. 모달의 초점은 내부에 유지하고 닫으면 호출한 요소로 돌아간다.
- 새 결과가 도착해도 사용자의 초점을 빼앗거나 현재 읽고 있는 목록을 무단 재정렬하지 않는다. 정렬 변경은 사용자 조작으로 수행하거나 명확하게 안내한다.
- 조사 시작·완료·중요 실패는 읽기 기능으로 안내한다. 개별 요청이나 공고마다 알림을 반복하지 않고 의미 있는 상태 변화와 누적 결과 수를 묶어 알린다. 알림이 현재 낭독을 불필요하게 끊지 않게 한다. 의미를 알 수 없는 진행률 수치를 만들지 않는다.
- 오류 메시지는 해당 입력과 연결하고 수정 방법을 설명한다. 색상·진동·소리만으로 오류나 상태를 전달하지 않는다. 네트워크 실패 후 재시도 시 가능한 한 입력과 탐색 위치를 유지한다.
- 시스템 글자 크기 확대 시 핵심 텍스트와 조작 요소가 잘리거나 겹치지 않도록 한다. 충분한 대비와 터치 영역, 단순한 문장과 탐색 구조를 적용한다.
- 스와이프·드래그 등 복잡한 제스처에만 의존하는 조작은 제공하지 않는다. 일반 버튼과 화면 읽기 기본 조작으로 같은 기능을 수행할 수 있게 한다.
- 날짜에는 연도와 시간 정보를 필요한 범위에서 포함하고, 한국 시간 기준임을 명확히 한다. 금액의 단위와 범위를 낭독해도 이해할 수 있게 한다.
- 원문 링크에는 문서 또는 사이트의 성격을 표시하고 외부 이동임을 알린다. PDF 등 외부 자료의 접근성을 앱이 보장한다고 표현하지 않는다. 앱 내 구조화된 요약과 원문 접근 경로를 함께 제공한다.
- 맞춤 조건 같은 개인정보가 접근성 알림, 화면 오류, 분석 이벤트에 불필요하게 노출되지 않게 한다.

## 서버·조사 역할과의 인계

서버에 공고 고유 식별자, 공급 유형, 지역, 모집 상태, 신청 기간, 구조화된 상세 정보, 공식 근거 URL, 확인 시점, 검증 상태와 사유, 조사 작업 상태, 출처별 실패 여부를 요청한다. 각 필드의 미확인·해당 없음·없음 의미를 구분한다. 수집 실패를 검색 결과 0건으로 바꾸지 않는다.

정정·취소·마감 처리와 선별 결과의 설명 문구는 조사·검증 전문가와 합의한다. 화면이 상태를 임의 추론하지 않도록 서버 계약을 정하고, 불일치가 발견되면 근거와 함께 총괄에게 수정 요청한다. 로그인 만료, 저장 실패, 중복 조작은 성공한 것처럼 안내하지 않는다.

## 검수와 완료 기준

iOS VoiceOver와 Android TalkBack을 켠 실제 기기에서 다음 시나리오를 각각 수행하고 기기·운영체제·앱 버전, 결과, 결함, 재검증 결과를 기록한다. 수행하지 않은 검사는 미검증으로 명시한다. 자동 검사나 화면 캡처만으로 접근성 검수를 통과 처리하지 않는다.

- 비로그인으로 지역 입력 → 조사 진행 확인 → 목록 탐색 → 상세 읽기 → 공식 원문 열기 → 앱 복귀.
- 맞춤 검색 진입 → 조건 입력·수정·초기화 → 참고 선별 사유 확인.
- 저장 선택 → 로그인 → 원래 공고 복귀 → 저장 확인 → 저장 해제.
- 접수 예정, 접수 중, 확인 필요, 전체 0건, 일부 출처 실패, 전체 조사 실패, 정정·취소된 저장 공고 구분.
- 조사 도중 새 결과 도착, 검색 조건 변경, 재시도, 로그인 만료, 저장 실패 상황에서 초점·입력·상태 안내 확인.
- 최대 지원 글자 크기, 화면 읽기 순서, 모달·뒤로 가기 초점 복원, 알림 과다 여부 확인.

주요 흐름에 이름 없는 조작 요소, 도달할 수 없는 기능, 초점 갇힘, 사실과 다른 성공 알림이 없고 두 플랫폼 실기 검증을 완료해야 접근성 측면에서 시험 운영 가능으로 판정한다. 제한된 사용자 시험에 시각장애인 사용자를 포함하고 발견된 주요 작업 차단 문제를 해결한다. 미해결 문제와 지원 환경의 한계는 총괄 및 품질 검토자에게 보고한다.
