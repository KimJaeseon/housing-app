# 검수 기준

각 항목에 통과/실패/미실행, 증거 경로, 검증 일자, 담당자를 기록한다. 이 목록을 생성했다는 사실은 검사를 통과했다는 의미가 아니다.

## 범위와 정보 정확성
- [ ] 서울·경기·인천 지역 입력과 동명 지역 구분이 작동한다.
- [ ] 공공 임대·공공분양은 포함하고 민간 분양은 제외한다.
- [ ] 접수 시작·마감 경계와 여러 접수 차수를 한국 시간으로 판단한다.
- [ ] 취소·정정·마감·단순 공급계획이 활성 목록에 잘못 들어가지 않는다.
- [ ] 날짜·금액·단위·신청 조건을 공식 원문과 대조한 증거가 있다.
- [ ] 공고별 원문 링크·확인 시점과 항목별 근거를 추적할 수 있다.
- [ ] 불확실·충돌 공고는 확인 필요 목록으로 분리되고 이유가 표시된다.
- [ ] 기관별 중복 공고를 합칠 때 근거와 변경 이력이 보존된다.

## 검색과 맞춤 조건
- [ ] 매 검색마다 새 조사 작업을 실행하고 이전 결과는 최신 확인 결과로 오인시키지 않는다.
- [ ] 정상 무결과·부분 실패·전체 실패·조사 중 상태를 구분한다.
- [ ] 응답 지연·취소·재검색·첨부파일 추출 실패를 재현해 확인한다.
- [ ] 맞춤 검색은 선택이며 미입력 조건을 충족으로 처리하지 않는다.
- [ ] 맞춤 결과에 근거·판단 불가 조건·공식 확인 필요 안내가 있다.

## 계정과 데이터
- [ ] 로그인 없이 기본·임시 맞춤 검색이 가능하다.
- [ ] 관심 공고·조건 저장 시 로그인을 안내하고 원래 작업으로 복귀한다.
- [ ] 사용자 A가 사용자 B의 저장 데이터를 API 직접 호출로도 읽거나 변경할 수 없다.
- [ ] 저장 조건과 관심 공고를 삭제할 수 있고 비로그인 조건은 기본적으로 영구 저장하지 않는다.
- [ ] 비밀키·인증 토큰·개인 조건이 앱 배포 파일이나 로그에 노출되지 않는다.

## 접근성 — 두 운영체제에서 별도 기록
- [ ] 화면 읽기만으로 검색·결과 이동·상세·원문 열기·복귀가 가능하다.
- [ ] 화면 읽기만으로 맞춤 입력·오류 수정·로그인·저장·삭제가 가능하다.
- [ ] 제목·버튼·필드 이름·상태·초점 순서가 명확하고 초점이 갇히지 않는다.
- [ ] 진행 상태와 신규 결과가 과도한 음성 반복 없이 전달된다.
- [ ] 큰 글씨에서 내용·버튼이 잘리지 않고 색상만으로 상태를 전달하지 않는다.
- [ ] 지도 없이 주소·지역명으로 위치를 이해할 수 있다.
- [ ] 외부 원문 문서의 접근성 한계가 있어도 앱 요약·출처 정보로 복귀할 수 있다.

## 시험 운영 인계
- [ ] 실제 공식 출처 연동 범위와 미지원·실패 출처가 명시되어 있다.
- [ ] 실행·설정·장애 대응·사용자 데이터 삭제 절차가 있다.
- [ ] 대표 실제 공고와 재현용 경계 사례를 모두 검사했다.
- [ ] 차단 문제가 없고 미실행 필수 검사가 없다.
