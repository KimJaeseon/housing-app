# LH 실제 연결 검증

검증일: 2026-09-16 (Asia/Seoul)
판정: 저장된 키 자동 사용과 실제 목록 API 연결 통과. 공고 검증·앱 실제 목록 표시는 미완료.

## 실행 결과

- Windows DPAPI 암호화 파일 상태: ready. 키 값·암호문·인증 요청 URL·원응답은 기록하지 않았다.
- 조회 조건: 공고게시일 2026.09.01, 공고마감일 2026.09.30, 서울 11, 임대주택 06, PAGE=1, PG_SZ=3.
- 이 작업의 실제 목록 API 요청은 총 5회: 최초 연결, 구조만 확인, 공개 필드 확인, 수정 검사기 확인, 서버 흐름 확인. 자동 재시도·페이지 순회는 수행하지 않았다.
- HTTP 200, resHeader[0].SS_CODE=Y.
- dsList 행 수 2, 두 행의 ALL_CNT=2. 전체 기관/유형/날짜를 포괄하는 결과 수가 아니다.
- 확인된 구조: [{dsSch: [요청 조건]}, {dsList: [목록], resHeader: [응답 상태]}]. dsSch는 요청 조건을 반영하므로 원응답을 통째로 로그·표본 파일에 보관하지 않는다.
- 검사기를 실제 구조에 맞춰 수정했다. 성공 코드의 재귀 탐색 대신 정해진 위치·형식, 공고 식별 필드, 중복 행·순번, 총건수 일관성을 검사한다.
- 안전한 출력: json_shape=list_envelope_validated, candidate_row_count=2, reported_total_count=2, notice_verification=pending. 목록 포장 구조 검증과 공고 내용 검증을 구분한다.

## 검색 서버 연결

FastAPI TestClient의 실제 collector를 사용했다(HTTP 계층은 로컬 테스트 클라이언트, 외부 LH 호출은 실제 요청).

- POST /v1/search-jobs: 202.
- 저장된 파일의 키 자동 사용 후 RESPONSE_VERIFICATION_PENDING 도달.
- 현 구현에서 최종 job_status=failed, notices=[]를 유지한다. 이는 키 인증 실패가 아니라 실제 공고 검증기가 아직 연결되지 않았음을 나타낸다.
- 이번에 실제 공고 목록·상세 화면까지 완료된 것으로 보고하지 않는다.
