# 공고별 공급정보 연결 및 검증 기록

2026-09-17 / Windows / Python 3.12 가상환경 / Expo React Native 웹 / headless Microsoft Edge + Playwright + axe-core.

목록 다음 단계로 상세 화면에서 주택형 공급정보를 요청하고 표시하는 기능을 구현했다. 실제 공급정보 성공 응답 검증은 별도 API 활용승인 확인 후 진행해야 한다. 현재 단계는 시험 운영 완료나 공고 검증 완료가 아니다.

## 명세와 구현 범위

- 공식 출처: [한국토지주택공사 분양임대공고별 공급정보 조회 서비스](https://www.data.go.kr/data/15056765/openapi.do).
- 공식 첨부 문서: `docs/references/LH_supply_API_20260202.docx`. 포털의 문서 다운로드 경로로 받은 원본이며 추출 텍스트를 같은 폴더에 보관했다. 20260708 목록 가이드와는 별도의 공급정보 가이드다.
- 요청: HTTPS `B552555/lhLeaseNoticeSplInfo1/getLeaseNoticeSplInfo1`, serviceKey, SPL_INF_TP_CD, CCR_CNNT_SYS_DS_CD, PAN_ID, UPP_AIS_TP_CD, AIS_TP_CD. 키는 기존 DPAPI 파일에서 서버만 읽는다.
- 지원: 유형 061/062/063 + 상위유형 06 + 시스템 03의 dsList01/dsList01Nm 레이아웃. 다른 레이아웃을 임의 변환하지 않는다.
- dsSch 공고 식별자 대조, 성공 헤더, 필드 형식, 1MiB 응답 크기, 100개 주택형 상한, 10초 네트워크 제한을 적용한다. 원문 요청 URL·키 반사값·응답 전체는 앱/로그로 넘기지 않는다.
- 전용/공급면적, 전체/금회공급 세대수, 보증금, 월 임대료를 개별 fact로 변환한다. 숫자와 명시된 단위 모두 맞아야 known이다. ‘공고문 참조’, 누락값, 잘못된 숫자, 단위 미확인은 unknown이다. 가이드 예제의 ‘공급면적’에는 단위가 없어 ㎡로 추정하지 않는다. 면적 소수점은 최대 8자리까지 표시한다.
- 주소·접수 일정·신청 자격은 이 레이아웃만으로 확인되지 않는다. 버전 관계는 unclassified, 공고는 needs_review를 유지하며 마감 공고를 활성 목록으로 옮기지 않는다.

## 앱과 서버 계약

`POST/GET /v1/search-jobs/{job_id}/notices/{notice_id}/supply`로 공급정보를 생성/조회한다. 부모 검색의 세션 소유권을 확인하고, 검색에서 얻은 공고 식별자만 사용한다. 클라이언트에서 임의 외부 URL이나 인증키를 받지 않는다.

동일 검색·공고는 같은 결과를 재사용한다. 동시 처리량은 기존 작업 슬롯을 공유한다. 실패 후 승인 상태가 변경되면 새 검색에서 재요청한다. 화면 이탈 시 클라이언트 조회를 중단하며, 이미 시작된 서버의 한정된 외부 요청은 종료될 수 있지만 이탈한 화면에 결과를 적용하지 않는다. 완료/실패 안내는 초점을 강제로 이동시키지 않는다.

상세의 공급정보 조회 버튼, 로딩, 주택형별 값·미확인 사유·근거 위치·한국 시간, 정상 빈 결과와 실패를 구현했다. iOS는 상태 변경을 대기열 음성 안내로, Android/웹은 polite live region으로 전달한다. 실기 낭독은 아직 검사하지 않았다.

정상 금액·0원·공고문 참조·단위 미확인·오류·공고 불일치·키 반사·네트워크 실패·세션 소유권·중복 요청·잘못된 공급결과 차단을 테스트했다. 웹에서는 소수점 보존, 미확인과 0 구분, 320px 가로 넘침 없음, 화면 이탈 후 늦은 응답 무시, 목록 복귀 초점을 확인했다. 합성 공급정보를 실제 성공 응답으로 보고하지 않았다.

코드 검토와 캡처 시각 점검을 수행했다. `frontend/qa/supply-available.png`, `supply-narrow.png`, `supply-empty.png`, `supply-failed.png`, `supply-malformed.png`, `supply-loading.png`가 신규 화면 증거다. 캡처와 axe 검사는 모바일 낭독·최대 시스템 글자 크기 검사를 대신하지 않는다. 영향 항목 A03~A07의 실기 검증은 사용자 실행 안내에 남겼다.

구조화된 결과는 `2026-09-17_SUPPLY_CHECKS.json`, 파일 해시 및 키 노출 검사 범위는 `2026-09-17_SUPPLY_HASHES.json`에 기록했다. 현재 FastAPI TestClient가 httpx 관련 사용 중단 예정 경고를 출력하지만 테스트는 통과했다.

## 다음 진행

1. 사용자가 포털에서 **공고별 공급정보 조회 서비스**의 활용신청 승인 여부를 확인한다. 키 자체를 전달할 필요는 없다.
2. 승인 반영 후 새 검색에서 실제 공급정보 응답을 확인하고 원문과 대조한다.
3. 공식 첨부 공고문에서 접수 회차·자격·금액 조건과 최종 정정 관계를 검증하는 단계를 구현한다. 현재 공급정보만으로 확인 완료 판정을 만들지 않는다.
4. [직접 실행 및 테스트 안내](../guides/RUN_AND_TEST.md)의 모바일 화면 읽기 검사를 수행한다.


추가 상태 (2026-09-17): 사용자가 공급정보 API 활용신청 완료를 알렸다. 위의 이전 403 기록은 신청 전 점검 결과다. 신청 이후 승인 반영 및 실제 성공 응답은 아직 재확인하지 않았다. 키 재전달 없이 기존 암호화 파일로 새 검색에서 확인한다.
