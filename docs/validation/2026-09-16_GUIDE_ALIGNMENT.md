원본 DOCX는 수정하지 않았다. 요청 메시지 명세, 지역·유형·상태 코드표, 응답 메시지 명세·예시, OpenAPI 오류 코드표를 구조적으로 추출하여 코드와 대조했다. 문서의 시각적 레이아웃 검수나 재편집은 작업 범위가 아니다.

## 요청

가이드에 따라 GET 요청을 공통 request_parameters 함수에서 구성한다.

| 항목 | 처리 |
|---|---|
| serviceKey | 소문자 시작 표기를 적용. 숨김 등록한 암호화 파일에서 읽고 URL 인코딩은 한 번만 수행 |
| PAN_ST_DT / PAN_ED_DT | 게시일 시작/종료, YYYYMMDD. CLI의 YYYY.MM.DD를 변환 |
| CLSG_ST_DT / CLSG_ED_DT | 선택적 마감일 시작/종료. 게시일 필터와 별개 |
| PAGE / PG_SZ | 1부터 시작, 가이드의 4자리 크기 내 양의 정수 검증 |
| PAN_NM | 선택 공고명, 최대 50자 |
| PAN_SS | 공고중 / 접수중 / 접수마감 / 상담요청 / 정정공고중 |
| CNP_CD / UPP_AIS_TP_CD | 가이드 코드표 검증. 앱의 현재 수집 범위는 계속 서울·인천 및 임대주택 06 |

가이드는 게시일 초기값을 현재일-2개월~현재일로 명시한다. 앞 단계에서 관찰한 기본 기간과 일치하며, 앞선 문서의 ‘실호출로만 관찰한 매개변수’라는 불확실성은 이번 가이드 확인으로 해소됐다. 문서의 HTTP 예시 대신 실제 동작을 확인한 HTTPS 엔드포인트를 유지한다.

앱 수집은 계속 명시적으로 설정한 게시일 범위를 사용한다. 공고명·상태·마감일 옵션은 현재 단일 호출 검사 CLI에 제공하며 앱 검색 폼에 새 입력란을 추가하지 않았다.

## 응답

- [{dsSch:[...]},{resHeader:[...],dsList:[...]}] 구조와 성공 코드 Y를 확인한다. 요청 반영부 dsSch는 비밀정보를 포함할 수 있으므로 반환·로그·증거 파일에 복제하지 않는다.
- 목록의 RNUM·ALL_CNT와 공고 식별자로 중복·누락·총건수 변경을 검사한다. 숫자 문자열은 가이드의 10자리 범위를 수용한다.
- PAN_NT_ST_DT(게시일), CLSG_DT(목록 마감일), 선택 PAN_DT(모집공고일)를 구분한다. PAN_DT가 없으면 null로 유지한다.
- 후속 상세 조회에 필요한 SPL_INF_TP_CD, CCR_CNNT_SYS_DS_CD, PAN_ID, UPP_AIS_TP_CD, AIS_TP_CD를 보존한다. 코드 길이 설명과 표본 길이가 다르므로 선행 0을 지우거나 임의로 자르지 않는다.
- 공고상태의 앞뒤 공백을 제거한다. ‘공고중’과 ‘정정공고중’을 접수 중 또는 접수 예정으로 단정하지 않는다.
- DTL_URL / DTL_URL_MOB를 사용한다. 고정 mi=1026 링크를 임의로 만들지 않는다. 공식 호스트·허용 경로·매개변수·공고 식별자를 검증한다.
- 가이드에 함께 실린 현대 경로와 구형 /LH/index.html 경로를 구분해 처리한다. 링크가 없거나 식별자가 다르면 null로 보관하고 앱에서는 원문 링크 미확인을 안내한다. 구형 주소의 실제 서비스 운영 여부까지 보장하는 것은 아니다.
- 응답 예시의 일부 행에는 필수로 표시된 모바일 URL이 없고, 첫 행의 링크 ID와 PAN_ID도 다르다. 예시를 그대로 정상 공고 데이터로 사용하거나 누락 값을 추정하지 않는다.
- 목록 성공은 일정·금액·자격·정정 관계 검증 완료가 아니다. 실제 verified 차단과 needs_review 처리는 유지한다.

## 오류

가이드의 1,2,3,4,5,10,11,12,20,21,22,30,31,32,33,99 코드를 내부의 고정 오류 코드로 매핑했다. 0은 정상 상태 코드지만 목록의 성공 구조 검사를 생략하지 않는다.

- 등록되지 않은 키 / 만료된 키 / 일시 중지 / 접근 거부 / 미등록 IP를 구분한다.
- 22는 호출 제한, 5는 시간 초과, 10·11은 요청 조건 오류로 구분한다.
- 3 NODATA_ERROR는 정상 성공 응답의 빈 dsList와 구분하며 조사가 정상 완료됐다고 처리하지 않는다.
- 정상 응답은 JSON으로 처리한다. 게이트웨이 오류는 JSON 및 제한된 XML 오류 구조에서 숫자 코드만 읽는다. XML DTD·엔터티 선언은 거부한다.
- 원문 오류 문구·요청 URL·예외 메시지·비밀값은 사용자 응답과 로그에 포함하지 않는다. 매핑하지 못한 값은 고정 UNKNOWN 오류로 반환한다.
- 재시도 가능 표시는 일부 일시 오류에 한정하며 자동 재시도는 하지 않는다.

## 검증

- 서버 자동검사 92개 통과. 요청 매개변수·인코딩·범위 검사, 가이드 오류 코드 전부의 JSON/XML 합성 사례, 링크 검증, 식별자 보존, 키 반사 응답 차단을 포함한다.
- TypeScript 및 Expo 웹 빌드 통과.
- 웹 회귀 검사 24개 화면 상태의 axe 위반 0건, 링크·초점 등 동작 확인 8개 통과. 실제 모바일 화면 읽기 검사는 미실행이다.
- 실제 호출: 2026.08.01~2026.09.16 / 서울 / 임대주택 / 공고명 서울번동3 / 접수마감 / 마감일 9월 범위에서 HTTP 200, 2건.
- 동일 게시일 기간에서 마감일 종료를 2026.08.31로 설정: 성공 빈 목록. 접수중으로 제한: 성공 빈 목록.
- PAGE=2, PG_SZ=1: 전체조회건수 2, 해당 페이지 1건.
- 실제 수집기: 마감 2건 제외, 상세 링크와 공급정보 구분 코드 보존 확인.
- 인증 실패·제한 초과 등을 실제 키로 일부러 유발하지 않았다. 해당 오류는 합성 응답으로 검증했다.

## 직접 확인

프로젝트 루트 PowerShell:

```powershell
.\.venv\Scripts\python.exe -m backend.lh_probe --start 2026.08.01 --end 2026.09.16 --region 11 --type 06 --page 1 --page-size 3 --name 서울번동3 --status 접수마감 --closing-start 2026.09.01 --closing-end 2026.09.30
```

승인키를 명령행에 넣지 않는다. 기존 파일에서 자동으로 읽는다. 결과는 실제 시점의 공식 자료에 따라 달라질 수 있다.

이후 단계: 가이드가 언급하는 분양임대공고별 공급정보 조회 API의 별도 명세를 확인하고 보존한 식별자를 이용해 원문 근거 검증을 연결한다. 현재 파일은 목록 API 명세이므로 상세 API 경로·요청 규격을 추정해서 호출하지 않았다.

최종 추가 확인: 참조 판정 규칙 26개 통과. 수정된 클라이언트로 실제 LH → HTTP 서버 → 앱 목록·상세를 재검사했고, 4개 상태에서 axe 위반 0건 및 가로 넘침·복귀 초점 2개 검사 통과.
