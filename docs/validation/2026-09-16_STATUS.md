## 코드에서 확인한 구현 상태

- Expo 화면, FastAPI 검색 작업 생성/조회/취소, 임시 세션별 접근 분리, 중복 요청 처리, 제한된 백그라운드 실행이 구현되어 있다.
- 프론트 기본 모드는 서버 연결이며 가상 예시는 별도로 전환한다. 현재 UI는 서울 전체 검색이다. 서버는 서울·인천 입력을 지원하고 경기 시·군은 미지원이다.
- LH 어댑터는 연결 검사 단계다. 성공 신호가 있어도 RESPONSE_VERIFICATION_PENDING을 반환한다.
- backend/app.py의 작업 처리기는 현재 실패 상태만 종료 결과로 생성하고 실제 notices를 채우지 않는다.
- backend/validation.py는 검증 어댑터 미구현 때문에 verified 공고를 모두 거부한다. 미검증 공고 노출을 막는 의도된 제한이다.
- frontend/useSearchApi.ts는 실제 공고가 오더라도 상세 표시 연결이 필요하다는 상태 문구만 제공한다. 실제 목록/상세 데이터 매핑은 미구현이다.
- 로그인·관심 저장·조건 저장·삭제·맞춤 검색은 미구현이다. 임시 세션 검사는 계정 데이터 권한 검사와 다르다.
- 현 실행 프로세스의 LH_SERVICE_KEY 환경변수는 발견되지 않았다. 다른 터미널이나 별도 저장소의 키 보유 여부는 판단하지 않았다. 실제 LH 요청은 실행하지 않았다.

## 발견한 문서 불일치

1. docs/frontend/README.md에 mobile 폴더 실행 안내가 남아 있으나 실제 폴더는 frontend다.
2. 같은 문서의 처음에는 서버 미연결이라고 쓰여 있고, 뒤에는 기본 서버 연결이라고 되어 있다. 실제 코드는 후자다.
3. docs/backend/API_TEST_GUIDE.md 서두는 도구가 서버 어댑터로 미연결이라고 하지만 backend/lh_adapter.py에는 제한적 연결 검사 통합이 있다.
4. 과거 NEXT_STEPS.md의 데이터 계약 초안 및 서버 연결 착수 안내와 과거 검사 개수는 현 상태보다 오래된 기록이다. 역사 기록과 최신 실행 안내를 구분해야 한다.

## 다음 실행 순서

1. 최신 실행 안내를 frontend 경로와 현재 연결 상태에 맞춰 정리한다.
2. 승인된 LH 키를 로컬 숨김 입력으로 사용해 실제 API 연결을 검사한다. 키를 대화나 파일에 기록하지 않는다. 날짜 필터 의미는 최신 공식 가이드와 표본에 맞춰 확인한다.
3. 실응답 구조·빈 결과·인증 오류·제한·페이지 중복/누락을 구분하는 어댑터를 구현한다. 현재 단일 페이지 연결 검사는 이 검증을 대신하지 않는다.
4. 허용된 원문/첨부 경로를 확보하고 대표 공고의 정정·취소·접수 일정·금액·자격과 근거를 대조한다. 검증 요건 충족 시에만 verified를 허용한다.
5. 실제 검증 결과를 서버 notices → 프론트 목록 → 상세 → 공식 원문으로 연결한다. 합성 계약 표본을 통한 화면 매핑 개발은 키 준비와 병행 가능하다.
6. 실제 Android TalkBack·iOS VoiceOver로 검색·상세·원문 복귀를 검사한다. 화면 구현 과정부터 시행하고 시험 운영 전 완료한다.
7. 경기 시·군과 기관 범위 확장, Supabase 로그인·저장·삭제·계정별 권한 검증을 진행한다.

가장 먼저 달성할 기능 목표: 서울의 LH 실제 공고 1건을 근거 검증 후 앱 목록과 상세에서 확인하는 전체 흐름. 승인키 보유만으로 원문 접근 및 정보 검증이 완료되는 것은 아니다.
