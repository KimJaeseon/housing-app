[제17조의2](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1030903657)는 통합공공임대주택 입주자 선정의 세부 기준을 별표 5의2로 연결한다. 별표 5의2의 해당 시행본 전체와 공고 첨부 양식의 조문별 대조는 아직 검증되지 않았다. 따라서 법령 적용으로 공고의 소득·자산 수치를 수정하거나 자격을 확정하지 않는다. 현재 시점의 법령을 9월 17일에 소급 적용하지 않는다.

## 3. 검증 사유 API와 화면

`GET /v1/search-jobs/{job_id}/notices/{notice_id}/verification`은 소유자 세션과 기존 목록 공고를 확인한다. 목록의 복합 ID `LH-2015122300020807-48-03`과 공식 ID `2015122300020807`이 모두 일치할 때만 강서염창 보존 PDF·검토·93규칙·별도 공지 스냅샷의 무결성을 읽고 사유 코드를 반환한다. 이번 조회의 공고문 응답이 검토 기록과 같은 현재/원공고 ID, SHA-256, `reviewed=true`, `partial`일 때만 `live_document_bound=true`로 표시한다. 다른 공고에 강서염창 규칙을 재사용하지 않는다. 응답은 신청자 정보를 받지 않고 항상 `needs_review`, `eligible_for_promotion=false`, `applicant_evaluation=false`다. 앱 상세 화면에서 `검증 사유 확인`으로 확인할 수 있다.

다음 구현 작업은 14쪽 금액표와 28~31쪽 갱신 구조를 별도 근거 단위로 검토하고, 공식 별표·첨부 양식을 확보해 조문별 대조하는 것이다. 별도 공지와 모집공고의 직접 관계·정정 여부를 증명한 뒤에만 해당 보류 사유를 해제할 수 있다. 그 후 긍정/부정 판정 사례를 갖춘 운영 판정기를 구현해야 `verified` 후보를 다룰 수 있다. VoiceOver·TalkBack 실제 기기 검사는 사용자 요청에 따라 뒤로 미뤘다.

검증: 백엔드 218개, 참조 규칙 26개, TypeScript 검사, Expo 웹 빌드 및 Chrome 화면 QA를 통과했다. 화면 QA의 새 `verification-needs-review` 상태에서 자동 접근성 위반은 없었다. 별도 LH 검색은 명시한 조회 범위의 수동 실시간 확인이며, 변경 공지의 전수 조사 또는 공고 ID 관계 증명 검사가 아니다.

사용자 확인 순서: 로컬 서버를 다시 시작하고 서울 공고를 새로 조회한 뒤 강서염창 상세에서 `공고문 항목 확인`과 `검증 사유 확인`을 차례로 누른다. 문서가 일치하면 `원문 일치: 이번 조회에서 확인됨`을 볼 수 있지만 상태는 `확인 필요`여야 한다. 강서염창이 그날 목록 기간에 없거나 마감·취소 탭에 있다면 공식 원문 링크에서 현재 상태를 확인하고, 이를 모집 가능 상태로 해석하지 않는다.
