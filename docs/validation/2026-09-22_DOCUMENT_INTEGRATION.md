# 원문 항목 확인 기능 — 구현·검증 기록

2026-09-22. 중단된 원문 조회 기능의 서버 API, 화면, 검증을 마무리했다. 공고 전체 자동 검증기는 아직 완성되지 않았다.

## 실제 자료와 확인 범위

대상은 `[정정공고]서울번동3 행복주택 예비입주자 모집`, PAN_ID 2015122300020605다. [공식 상세](https://apply.lh.or.kr/lhapply/apply/wt/wrtanc/selectWrtancInfo.do?panId=2015122300020605&aisTpCd=10&ccrCnntSysDsCd=03&uppAisTpCd=06&mi=1026)의 ‘공고문’ 그룹에서 [PDF 첨부](https://apply.lh.or.kr/lhapply/lhFile.do?fileid=68214585)를 확인했다. 팸플릿·신청서와 구분했다.

2026-09-17 PDF 29쪽을 텍스트 추출하고, 요약에 사용하는 1·2·3·12쪽을 렌더링해 시각 대조했다. 검토 기록은 `backend/document_reviews/2015122300020605.json`, PDF 원본은 `docs/references/lh-notice-2015122300020605.pdf`다. 추출·렌더링은 번들 pypdf와 Poppler로 수행했으며 실제 서버에 새로운 PDF 파서 의존성을 설치하지 않았다.

2026-09-22 09:01 한국 시간에 실제 목록을 다시 받아 서버 POST/GET 원문 경로로 재조회했다. 공식 PDF SHA-256은 `5deb8acbdb2112f274f67c3c03e01f754fa4fc986d45c30868e16bc001532f6f`로 검토 당시와 일치했다. 현재/원공고 ID와 정정 사유도 일치했고, 결과는 partial / reviewed=true / 17개 항목이다. 조회 시점과 기존 항목 검토 시점은 다른 개념이다.

확인 항목은 공급 위치, 신청 접수·서류제출·발표 일정, 계약 개별통보, 대상별 기본 임대조건 5행, 21A 유소득 청년의 최대 전환 조건 2개, 공급 대상 개요·예비입주자 모집·임대조건 적용 시점·전환 조건이다. 공고문 2쪽의 보증금은 천원 단위이므로 원 단위로 환산했다. 21A 대학생/무소득 청년과 유소득 청년의 조건을 합치지 않았다.

공급정보 API가 금액을 ‘공고문 참조’로 반환하는 사실은 유지한다. PDF 확인값을 별도 근거 영역에 표시한다. 계약 시점 금액 변경 가능성과 최대 전환의 선택 조건을 함께 표시한다. 해당 공고는 마감이며 활성 신청 공고로 승격하지 않았다.

## 구현

- `backend/lh_document.py`: 공식 URL·공고 ID·제목 확인, 상세의 단일 PDF 식별, 크기 제한, 리다이렉트 거부, PDF 서명과 SHA-256 대조. 사이트 스크립트를 실행하지 않고 공개 리터럴 메타정보만 읽는다.
- 검토 기록은 해당 공고 ID, PDF 해시, 원공고 ID, 현재 공고 ID, 정정 사유 모두 일치할 때만 사용한다. 변경 또는 미등록 PDF는 확인값 없이 재검토 안내를 반환한다.
- `POST/GET /v1/search-jobs/{id}/notices/{notice_id}/document`: 부모 검색 소유권 및 상태 확인, 중복 요청 결과 재사용, 기존 워커/슬롯 공유. 동일 검색의 실패·완료 결과는 새 검색 전까지 유지된다.
- 상세 화면의 ‘공고문 항목 확인’: 진행·오류·검토 필요·항목별 페이지 근거·외부 PDF 열기. 새 결과가 초점을 이동시키지 않으며 화면 이탈 시 앱 대기를 중단한다.
- `serve_lh`는 LH_ENABLE_DOCUMENT를 활성화한다. 일반 uvicorn 실행은 기본 비활성이다. 공개 웹/PDF 요청에 LH 서비스키를 보내지 않는다.
- 데이터 계약에 document_result를 추가했다. 원문 값은 읽기용 설명이며 자동 자격 판정 입력이나 검증 완료 공고로 사용하지 않는다.

## 남은 작업

1. 새 공고와 변경 PDF의 검토 기록을 확장하고, 추출·검토 절차를 일반화한다. 현재는 표본 한 건에 한정한다.
2. 전체 소득·자산 가산, 세대구성, 우선배정, 별도 일정 변경 공지를 검증한다. 현재는 공급 대상 개요만 제공하며 개별 적격 여부는 판단하지 않는다.
3. 검증 완료 판정기를 실제 근거와 연결한다. verified 생성 차단은 유지한다.
4. iOS VoiceOver와 Android TalkBack, 최대 시스템 글자 크기에서 직접 검사한다.

사용자 확인 경로는 [실행·테스트 안내 7절](../guides/RUN_AND_TEST.md), 통합 개발 기준은 [프로그램 명세서 1.1](../PROGRAM_SPECIFICATION.md)을 따른다.
