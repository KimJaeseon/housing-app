# 2026-09-16 목록 수집·앱 연결 검증

## 판정

선택한 게시일 기간의 LH 임대주택 목록을 페이지 단위로 조회하고, 원문 미검증 공고와 마감·취소 제외 공고를 구분하여 앱 목록·상세·공식 링크까지 연결했다. 원문 검증, 최종 정정 관계 확정, 실제 기기 접근성은 미완료다. 시험 운영 완료 판정이 아니다.

## 날짜 조회 원인과 수정

- 공식 포털 표에는 PAN_NT_ST_DT와 CLSG_DT가 요청변수로 안내돼 있지만, 실제 요청에서는 날짜를 바꿔도 같은 결과가 나왔다.
- dsSch의 공개 날짜 필드만 확인한 결과, 요청값과 달리 PAN_ST_DT=20260716, PAN_ED_DT=20260916이라는 기본 기간이 적용되고 있었다.
- 실제 응답에 나타난 PAN_ST_DT/PAN_ED_DT를 YYYYMMDD 형태로 요청하여 기간 반영을 확인했다. 이는 공식 문서 표와 차이가 있는 실호출 관찰이며 기관이 모든 조건에 대해 보장한 명세로 확대 해석하지 않는다.
- 20260901~20260930은 0건, 20260801~20260930은 2건. 20260819~20260819와 20260821~20260821은 각각 해당 게시일 공고 1건을 반환했다.
- 실제 목록 수집은 요청 기간·지역·유형·페이지·페이지 크기와 dsSch가 일치하는지 확인한다. 각 행의 게시일이 지정 범위 밖이면 실패 처리한다.
- CLI는 --start / --end를 사용한다. 이전 --posted / --closing은 별칭이며 이제 두 값 모두 게시일 기간을 뜻한다. 목록의 CLSG_DT는 별도 공개 값이며 실제 접수 종료시각으로 변환하지 않는다.

공식 문서 비교 출처: https://www.data.go.kr/data/15058530/openapi.do

## 페이지·상태 처리

- 실제 API에서 PAGE=1/2, PG_SZ=1로 원공고·정정공고가 서로 다른 순번에 반환됨을 확인했다. PAGE=3은 정상 빈 목록이다.
- 기본 20건 × 최대 5페이지. 페이지 사이에 35초 경과 여부와 취소를 확인하며 개별 요청의 연결/읽기 timeout은 최대 10초다. 전송이 지연되는 모든 상황에 대한 강제 총시간 종료를 보장하지는 않는다.
- 자동 재시도 없음. 페이지 중복·순번 누락·총건수 변경·조기 빈 목록·페이지 상한 도달을 구분한다. 일부 수집 후 실패하면 확보된 미검증 결과와 미완료 범위를 함께 유지한다.
- 같은 제목만으로 정정본과 원공고를 합치지 않는다. 정정 단서는 검토 사유로 남기고 최종 버전을 지정하지 않는다.
- 마감·취소는 active notices에서 제외하고 excluded_notices에 보관한다. 기본 신청 가능 목록에 노출하지 않는다.
- 모든 실제 공고는 needs_review, revision_resolved=false다. verified 차단은 유지한다.
- 목록이 정상 종료돼도 공고 검증과 기관 범위가 미완성이므로 작업은 partial이다. 출처의 DOCUMENT_VERIFICATION_PENDING은 API 인증 실패가 아니라 공고 검증 미완료를 뜻한다.

2026.08.01~2026.09.16 / 서울 / LH 임대주택: API 요청 → 파일 키 자동 읽기 → 목록 2건 → 마감 2건 제외 → 앱 제외 목록 → 정정공고 상세.

- FastAPI 실제 collector + TestClient: 통과. 안전한 앱 응답만 2026-09-16_LH_LIST_RESPONSE.json에 저장했다.
- 실제 HTTP 서버 + Edge 웹앱 + 실제 LH 요청: 통과. 자동검사는 실제 목록 2건이라는 이번 표본을 사용하므로 원천 자료 변경 시 기대값 검토가 필요하다.
- 서버 키·요청 인증 URL·dsSch 원본·전체 원응답은 저장하지 않았다.
- 화면에는 LH 임대주택, 실제 요청 기간, 조사 페이지·건수, 미지원 기관과 원문 검증 제한을 표시한다.
- 상세에는 목록 날짜와 실제 접수 일정의 차이, 미확인 금액·자격, 확인 시점 및 공식 원문 버튼을 표시한다.
