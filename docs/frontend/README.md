# 모바일 초안 실행

2026-09-15 재개·검수. React Native + Expo TypeScript 초안이다. 기본 모드는 서버 연결이며, 가상 공고는 미리보기 모드에서만 표시한다. 실제 공고 목록·상세 매핑은 아직 미구현이다.

## 화면

서울 전체 검색 → 조사 진행/취소 → 결과/확인 필요 → 상세 → 이전 공고 초점 복원.
서울·서울시·서울특별시 및 공백 변형은 seoul로 정규화한다. 구 이름만 입력하거나 서울 중구처럼 입력하면 설명과 함께 거부한다. 구별 검색은 범위에 넣지 않았다. 서버에도 같은 별칭 처리를 반영했다.

## 실행

프로젝트 frontend 폴더에서 pnpm start로 Expo 개발 서버 실행. 웹 미리보기는 pnpm web. pnpm이 PATH에 없으면 이 환경의 번들 경로를 사용한다:

```powershell
cd C:\data\menual\housing-app-guidelines\frontend
& 'C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\bin\fallback\pnpm.cmd' web
```

## 변경할 때마다 검사

```powershell
pnpm exec tsc --noEmit
pnpm exec expo export --platform web
node qa.mjs
```

qa.mjs는 로컬 Edge headless와 임시 HTTP 서버를 시작하고 검사 종료 후 닫는다. 결과는 qa/results.json, 화면은 qa/*.png에 저장된다. 다른 환경에서는 Edge 또는 Playwright 브라우저 설정을 준비한다.

## 미실행 및 제한

실제 iOS VoiceOver·Android TalkBack, 시스템 최대 글자 크기, 노치·안전영역, 외부 문서 복귀, 로그인·저장·맞춤 입력 검사는 미실행이다. 일부 기능은 미구현이다. 실제 기기 검증 없이 시험 운영 가능으로 판정하지 않는다.

기본 결과 탭은 확인 완료 상태의 화면 배치 예시이며 실제 검증 데이터가 아니다. 상세의 미확인 값은 정보 부재 표현을 보여준다. API 연결 시에는 검증된 데이터만 기본 목록에 넣는 서버 계약을 반드시 적용한다.

향후 모든 화면 변경은 docs/design/ACCESSIBILITY_POLICY.md를 적용한다. 다음은 실제 기기 초안 검수와 서버 연결용 상태 매핑 구현이다.

## 모바일–서버 연결 단계

기본 모드는 실제 서버 연결이다. 가상 공고는 검색 화면의 '가상 화면 미리보기로 전환'으로만 표시한다. 현재 서버는 공고 검증이 미완성이므로 준비 상태/실패를 표시하며 실제 공고 카드의 필드 매핑은 후속 작업이다.

1. 프로젝트 루트에서 `.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8000 --no-access-log` 실행.
2. frontend 폴더에서 `pnpm web` 실행. 기본 웹 주소는 8081, API는 127.0.0.1:8000이다.
3. 서울 검색 → 서버 상태 확인 → 다시 조사하기. 새 요청에는 새 중복방지 키를 사용한다.

실제 휴대폰에서는 EXPO_PUBLIC_API_URL을 휴대폰에서 접근 가능한 개발 서버 주소로 설정하고 Expo를 재시작해야 한다. localhost는 휴대폰 자신을 가리킨다. 기기 연결·방화벽·개발 네트워크 검증은 미실행이다. 이 값은 공개 서버 주소만 포함하며 LH 인증키를 넣지 않는다.

동작: 메모리에만 임시 세션 토큰 보관, 10초 요청 timeout, 750ms 간격 조회, 약 60초 조회 한도. 이전 검색의 늦은 응답은 무시한다. 조회를 멈춰도 서버 작업이 끝났다는 뜻은 아니다. 취소는 서버 응답을 확인한 뒤 안내하며 실패하면 서버가 계속될 수 있음을 표시한다. 임시 세션은 계정 로그인이 아니다.

검사: 실제 로컬 HTTP 서버로 검색·재검색 후 ADAPTER_NOT_CONFIGURED 안내 확인. 취소/늦은 응답과 통신 실패는 합성 HTTP 응답으로 검증. 웹 접근성 결과는 qa/results.json. VoiceOver/TalkBack 실기 검사는 여전히 미실행이다.

qa.mjs는 8000 포트의 테스트 서버와 18800 포트의 웹 서버를 사용하므로 별도 서버를 종료한 상태에서 실행한다. 실제 LH 환경변수 활성화 없이 로컬 회귀 검사를 실행한다.
