# 초안부터 적용하는 모바일 접근성 검증 정책

작성일: 2026-09-10
근거: `PROJECT_BRIEF.md`, `roles/mobile-accessibility.md`, `design/MOBILE_CONTRACT_REVIEW.md` 및 사용자의 “접근성 검증은 초안부터 항상 진행” 요청.

## 적용 시점과 판정

초안, 기능 추가, 문구 변경, 화면 배치 변경, 상태 처리 변경마다 영향을 받는 접근성 검사를 수행한다. 화면이 완성될 때까지 검증을 미루지 않는다. 검사 범위와 실행 환경은 해당 변경 기록에 남긴다.

검사 결과는 `통과`, `실패`, `미실행`으로 구분한다. 자동 검사 통과는 해당 검사 항목에만 적용한다. 코드 검토, HTML 미리보기, 브라우저 키보드 검사와 캡처는 React Native 실제 기기의 VoiceOver·TalkBack 검사를 대신하지 못한다. 기기를 사용할 수 없으면 실기 검사는 `미실행`으로 기록하고 초안의 미검증 항목으로 남긴다. 두 플랫폼의 주요 과업 실기 검증 전에는 접근성 시험 운영 가능으로 판정하지 않는다.

## 매 변경의 자동 검사 및 검토

- 버튼·입력·제목·링크의 이름, 역할, 선택·비활성·진행 상태 전달을 확인한다.
- 입력 오류에 수정 방법이 있고 해당 입력과 연결되는지 확인한다.
- 검색 상태 및 공고 수를 사실대로 안내하고, 출처 실패를 0건으로 바꾸지 않는지 검사한다.
- 조사 결과 갱신이 목록을 임의 재정렬하거나 현재 초점을 이동시키지 않는지 확인한다.
- 색상만으로 상태를 전달하지 않는지, 일반 버튼으로 모든 동작에 접근할 수 있는지 검토한다.
- 텍스트 대비와 조작 요소 크기, 글자 확대 시 줄바꿈·잘림을 확인한다. 실제 렌더 검사를 하지 못했다면 스타일 숫자 확인만으로 통과 처리하지 않는다.
- 합성 공고에는 시험 자료임을 명확히 표시하며, 화면 초안을 실제 API 연동 결과로 안내하지 않는다.
- 접근성 알림, 오류, 검사 증거에 인증키와 개인 맞춤 조건을 포함하지 않는다.

자동 검사에는 실행 명령, 종료 코드, 검사 수, 검사한 코드 버전 또는 파일 상태를 기록한다. 사람이 검토한 사항은 자동 검사와 분리하여 대상 파일·화면·발견 사항을 남긴다. 실패는 수정 후 같은 시나리오로 재검증하며 회귀 영향이 있는 관련 화면도 확인한다.

## 서울시 검색 범위 계약

서울은 `서울특별시 전체`의 광역 단위 검색을 유지한다. 서울/서울시/서울특별시 등 지원하는 표기는 명시적 규칙에 따라 같은 범위로 정규화하고 제출 전·결과 화면·음성 안내에 실제 검색 범위를 표시한다.

구 단위 검색은 현재 명세의 범위가 아니다. 강남구 같은 구 입력을 서울 전체로 조용히 치환하거나 구 단위 필터를 임의로 추가하지 않는다. 지원하지 않는 입력에는 “현재 서울은 서울특별시 전체로 검색합니다”와 수정 또는 전체 범위 선택 경로를 제공한다. 사용자가 전체 범위를 선택한 경우에만 그 범위로 검색한다. 주소에 구 이름을 표시하는 것은 검색 범위를 구 단위로 확장한 것으로 취급하지 않는다.

서울의 모든 기관을 조사했다고 표현하지 않는다. 실제 연결한 출처, 실패한 출처, 미지원 출처와 결과가 합성 데이터인지 여부를 화면과 읽기 안내로 구분한다.

## 실제 기기 절차: iOS와 Android 각각 수행

아래 8개 절차를 iOS VoiceOver와 Android TalkBack에서 각각 수행한다. 시각적 도움 없이 화면 읽기의 기본 탐색·실행 조작으로 진행하고 필요한 경우 글자 확대 검사를 병행한다. 아직 구현하지 않은 기능은 해당 절차의 미실행 사유를 적는다.

| ID | 절차 | 기대 결과 |
|---|---|---|
| A01 | 비로그인 진입 → 서울 전체 선택 또는 지원 표기 입력 → 검색 | 이름·역할·선택 상태와 실제 서울 전체 범위를 이해할 수 있다. 지도나 로그인이 필요하지 않다. |
| A02 | 구 이름 또는 지원하지 않는 지역 입력 → 오류 확인 → 서울 전체를 명시적으로 선택 | 오류와 수정 경로를 읽고 도달할 수 있다. 입력이 몰래 다른 범위로 바뀌지 않는다. |
| A03 | 조사 시작 → 일부 결과 도착 → 완료, 부분 실패, 전체 실패와 정상 0건을 각각 재현 | 의미 있는 전환을 묶어 안내한다. 현재 낭독과 초점을 불필요하게 끊지 않으며 실패를 공고 없음으로 안내하지 않는다. |
| A04 | 기본 목록 탐색 → 확인 필요 목록 → 상세 → 뒤로 | 카드 읽기 순서가 공고명·유형·지역·모집 상태·신청 기간으로 일관된다. 확인 필요 사유를 읽고, 상세 진입 초점과 뒤로 가기 시 이전 항목·목록 위치가 복원된다. |
| A05 | 상세 날짜·시간·금액·미확인 값·정정 상태 확인 → 공식 원문 → 앱 복귀 | 한국 시간과 금액 단위를 이해할 수 있고 미확인을 0으로 읽지 않는다. 외부 사이트/문서 이동을 안내하고 앱 복귀 시 원래 상세 위치를 유지한다. |
| A06 | 조사 도중 새 결과 도착·재검색·재시도·취소, 모달 열기·닫기 | 새 결과가 초점을 빼앗지 않는다. 오래된 응답이 새 검색을 변경하지 않는다. 모달 내부 탐색과 호출 요소 복귀가 가능하며 초점이 갇히지 않는다. |
| A07 | 최대 지원 글자 크기로 검색·목록·상세·오류·모달 조작 | 주요 텍스트와 조작이 잘리거나 겹치지 않는다. 읽기 순서가 자연스럽고 이름 없는 요소나 도달 불가능한 기능이 없다. 상태는 색상 없이 구분된다. |
| A08 | 임시 맞춤 입력·초기화 → 저장 → 로그인 성공/취소/만료 → 원래 공고 복귀 → 저장 해제·실패 재시도 | 기본·임시 맞춤은 비로그인으로 가능하다. 서버 확인 전 성공 안내가 없고 입력·초점·복구 경로가 유지된다. 개인 조건을 불필요하게 음성 알림에 넣지 않는다. |

## 변경마다 남길 증거 양식

- 변경 식별: 날짜, 담당, 변경 내용, 코드 버전 또는 대상 파일
- 실행 환경: 실제/시뮬레이터/브라우저, 기기 모델, OS, 앱 빌드, 화면 읽기 버전·설정, 글자 크기
- 자동 검사: 명령, 결과, 검사 수, 로그 경로
- 수동 검사: A01~A08 중 영향받은 항목, 실행 단계, 기대/실제 결과, 통과/실패/미실행
- 증거: 캡처·영상·낭독 관찰 기록의 경로. 캡처만으로 낭독·초점 동작을 증명하지 않는다.
- 결함: 재현 단계, 주요 과업 차단 여부, 수정 대상, 재검증 결과
- 미실행: 미구현 기능/기기 없음 등 구체 사유, 다음 검증 시점

현재 이 정책 문서 자체는 실기 검사 결과가 아니다. A01~A08의 VoiceOver·TalkBack 실행 증거가 첨부되지 않았으므로 실기 검사는 모두 미실행 상태로 시작한다. 이후 실제 실행 기록만으로 상태를 갱신한다.
