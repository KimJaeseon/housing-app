# 모바일·접근성 계약 검토 및 검수 설계

작성일: 2026-09-10 · 작업: D02 · 상태: 계약 통합 검토 대기

이 문서는 PROJECT_BRIEF.md, roles/mobile-accessibility.md, CHECKLIST.md, WORKFLOW.md 및 validation/2026-09-09/NEXT_STEPS.md를 근거로 한 설계다. 실행 가능한 앱·서버에 대한 검사 결과가 아니다. 아래 검수는 모두 미실행이며 iOS VoiceOver·Android TalkBack 실기 검증도 미실행이다. API 필드명은 통합 JSON 계약에서 확정하며, 아래 표의 이름은 요구하는 의미를 설명한다.

## 1. 서버 응답에 필요한 의미

| 대상 | 필수 의미 | 앱의 사용 방식 |
|---|---|---|
| 검색 식별 | 검색 작업 ID, 응답 revision 또는 단조 증가 순서 토큰 | 현재 작업과 다른 응답 및 오래된 응답을 버리고 목록 되돌림 방지 |
| 검색 범위 | 입력 지역, 정규화 지역 코드·명칭, 조사 대상 출처 목록, 미지원 출처 | 서울·인천 광역 단위 및 경기 시·군 범위를 명시. 미지원 출처를 조사 완료로 오인시키지 않음 |
| 작업 상태 | 접수, 조사 중, 일부 결과 도착, 정상 완료, 부분 실패, 전체 실패, 취소 및 시작·종료 시각 | 최종 여부와 실패 여부를 별도로 해석. 결과 수만으로 상태 추론 금지 |
| 출처 상태 | 출처 식별자, 대기/진행/성공/실패/취소/미지원, 실패 단계·사유, 재시도 가능 여부 | 목록 조회 실패와 첨부 추출 실패를 구분. 결과 0건과 수집 실패를 구분 |
| 결과 집계 | 검증된 활성 결과 수, 확인 필요 수, 조사 완료·실패 출처 수 | 접수된 출처 대비 의미 있는 진행 상황을 안내. 임의 진행률 생성 금지 |
| 공고 식별 | 안정적인 공고·모집 단위·접수 회차 ID와 버전, 업데이트 시각 | 새 결과는 ID 기준 병합. 변경된 공고·회차를 중복 카드로 추가하지 않음 |
| 모집과 검증 | 모집 상태와 검증 상태를 독립 제공, 기본/확인 필요/비활성 분류, 사유 코드·설명 | 앱이 날짜·제목만으로 신청 가능 여부를 재판정하지 않음 |
| 날짜·값 | 값과 확인 상태, 시간대, 정밀도, 단위·범위, 근거 ID | 미확인 값을 0·빈 문자열·미충족으로 표시하지 않음. 시각 누락을 23:59로 보충하지 않음 |
| 원문 | 공식 URL, 문서 종류, 문서 버전, 확인 시각, 항목별 페이지/표/문단 위치, 정정·취소 관계 | 공식 출처 및 외부 이동 안내. 최신 정정본 미확인 사유 표시 |
| 맞춤 결과 | 조건별 일치/불일치/판단 불가, 사용한 조건·규칙/근거, 미입력·근거부족 사유 | 선택형 참고 선별. 미입력은 충족으로 취급하지 않음 |
| 저장 | 인증 필요/만료, 서버 확인 저장 상태, 저장 실패 및 재시도 의미 | 낙관적 UI를 쓰더라도 서버 확인 전 성공 음성 안내 금지 |

값 상태는 최소한 확인된 값, 확인 실패 또는 미확인, 해당 없음, 공식 근거상 값 없음의 의미를 구분한다. 숫자 0과 불리언 false는 확인된 실제 값으로 허용해야 한다. 오류 설명에는 토큰·인증키·맞춤 개인정보를 포함하지 않는다.

## 2. 검색·취소·재검색 표시 규칙

1. 검색 제출마다 새 조사 작업을 만든다. 동일 지역의 이전 결과를 보여줄 때는 이전 확인 시각과 새 조사 진행을 함께 알리고 새 조사에서 검증된 결과로 표현하지 않는다.
2. 정상 무결과는 모든 실제 조사 대상이 정상 종료했고 활성 결과와 확인 필요가 모두 0인 경우에만 단정한다. 확인 필요만 있으면 해당 수와 진입점을 보여준다. 미지원 출처가 있으면 항상 검색 범위 한계를 표시한다.
3. 일부 출처 성공·일부 실패이면 검증된 결과는 제공하되 부분 실패 안내를 유지한다. 성공한 출처가 0건이어도 실패 출처가 있으면 전체 지역의 공고가 없다고 말하지 않는다.
4. 전체 조사 실패는 재시도 가능한 오류 화면을 제공하며, 확인 필요 공고가 남으면 별도 접근을 허용한다. 첨부 실패 공고는 근거 충족 여부에 따라 서버 판정을 따르고 앱이 자동으로 활성 목록에 넣지 않는다.
5. 취소 요청 중과 서버가 확정한 취소를 구분한다. 취소 전 수신 결과는 불완전한 조사 결과로 남길 수 있으나 정상 완료로 표시하지 않는다. 취소 응답과 완료 응답이 경합하면 서버가 확정한 최신 revision을 따른다.
6. 재검색은 새 작업 ID를 활성화한다. 이전 작업 응답이 늦게 와도 새 검색 목록·진행 안내를 변경하지 않는다. 이전 서버 작업의 중단 실패가 새 검색 결과에 섞이는 이유가 되어서는 안 된다.
7. 재시도 단위(출처 재시도 또는 새 조사)는 API가 명시한다. 재시도 도중 입력·현재 목록 위치를 가능한 한 보존한다. 결과가 추가되어도 읽고 있는 목록을 자동 재정렬하지 않는다.

## 3. 화면·접근성 인계

- 기본 카드의 읽기 순서: 공고명 → 공급 유형 → 지역 → 모집 상태 → 신청 기간. 확인 필요 카드는 사유를 함께 읽으며 신청 가능 표현을 사용하지 않는다.
- 상세: 모집 단위·회차를 구분하고 금액은 보증금/월 임대료/분양가 및 원·만원 등 단위를 명시한다. 텍스트 주소로 위치를 설명한다.
- 서버는 정확한 상태·집계·오류를 제공하고 모바일은 의미 있는 상태 전환을 묶어 안내한다. 공고마다 접근성 알림을 반복하거나 개인 조건을 음성 진행 알림에 넣지 않는다.
- 화면 진입 시 제목으로 초점 이동, 뒤로 가기 시 이전 항목과 위치 복원, 모달 종료 시 호출 요소로 복귀한다. 새로운 결과는 현재 초점을 빼앗지 않는다.
- 색상·아이콘·복잡한 제스처만으로 상태나 기능을 전달하지 않는다. 모든 동작에 읽을 수 있는 이름과 역할, 일반 버튼 경로를 제공한다.
- 외부 링크는 사이트 또는 PDF 등 종류와 외부 이동임을 안내한다. 원문을 열고 앱에 돌아오면 원래 상세 위치로 복귀한다. 외부 문서의 접근성을 보장한다고 표현하지 않는다.

## 4. 비로그인 맞춤 및 저장 복귀

기본·임시 맞춤 검색은 비로그인 상태에서 끝까지 가능해야 한다. 조건마다 입력 목적과 단위를 제공하고 초기화와 미입력을 허용한다. 미입력으로 발생한 판단 불가와 실제 불일치는 별도 표시한다.

관심 저장 또는 조건 저장을 누른 경우에만 로그인으로 연결한다. 로그인 전 보관하는 동작은 대상 ID와 원래 화면·초점 등 최소 정보로 구성하고, 맞춤 입력의 계정 영구 저장은 명시적 조건 저장 동작에 한한다. 로그인 취소·실패 시 원래 화면에 복귀하고 저장 성공을 알리지 않는다. 인증 성공 후 원래 동작을 한 번 수행하며 중복 제출을 방지한다. 로그인 중 공고가 취소·마감되면 최신 상태를 알리고 저장 사실을 신청 가능 안내와 분리한다. 저장/해제는 서버 확인 후 완료를 안내하며 만료·통신 실패 후에도 현재 상태와 복구 경로를 제공한다.

## 5. 재현 시나리오와 예상 결과

아래는 합성 입력으로 수행할 설계 사례다. 실제 공고와 혼합하지 않는다. 각 실행 기록에는 사례 ID, 플랫폼·기기·OS·앱/서버 버전, 일자·담당, 통과/실패/미실행, 증거 경로, 결함·재검증 결과를 남긴다.

| ID | 입력·사건 | 예상 결과 | 현재 |
|---|---|---|---|
| M01 | 비로그인 지역 검색, 검증 결과 단계적 도착 | 조사 중 표시를 유지하며 결과 탐색 가능. 초점 유지, 누적 수 안내를 묶음 | 미실행 |
| M02 | 모든 지원 출처 정상 종료, 활성·확인 필요 모두 0 | 조사 범위를 밝힌 무결과 표시. 실패 메시지 없음 | 미실행 |
| M03 | 한 출처 성공 0건, 다른 출처 시간 초과 | 부분 실패와 재시도 표시. 공고 없음으로 단정하지 않음 | 미실행 |
| M04 | 모든 출처 실패 | 전체 실패 표시. 재시도 시 지역 입력 보존 | 미실행 |
| M05 | 목록 확보, 첨부 추출 실패 및 확인 필요만 존재 | 확인 필요 수·사유·원문 경로 제공. 활성 공고 0건과 별도 설명 | 미실행 |
| M06 | 검색 A 지연 중 검색 B 제출, A 응답이 나중 도착 | B의 결과·음성 안내만 갱신. A 응답 배제 | 미실행 |
| M07 | 조사 중 취소, 결과 또는 완료가 취소 응답과 경합 | 최신 서버 상태 적용. 취소 결과를 정상 완료·0건으로 안내하지 않음 | 미실행 |
| M08 | 동일 결과의 중복 응답과 revision 역전 | 공고 중복 없음, 최신 상세 내용이 이전 버전으로 되돌아가지 않음 | 미실행 |
| M09 | 접수 마감 시각 누락, 회차별 날짜 차이 | 서버 검증·분류 유지. 날짜에 임의 시각 추가 금지, 회차별 표시 | 미실행 |
| M10 | 보증금 0원, 월세 미확인, 분양가 해당 없음 | 0원·확인되지 않음·해당 없음의 구분을 화면과 낭독으로 확인 | 미실행 |
| M11 | 소득 미입력, 자산 조건 불일치 | 소득은 판단 불가, 자산은 불일치. 자격 확정 문구 없음 | 미실행 |
| M12 | 비로그인 임시 조건 입력·검색·초기화 | 로그인 요구 없음, 명시적 저장 없이 계정 영구 저장 없음 | 미실행 |
| M13 | 저장 → 로그인 성공/취소/실패 | 원래 화면 복귀, 성공일 때 한 번 저장. 취소·실패는 성공 안내 없음 | 미실행 |
| M14 | 저장 중 세션 만료·연속 탭·네트워크 실패 | 중복 저장 및 거짓 성공 안내 없음. 복구 가능, 초점 유지 | 미실행 |
| M15 | 저장 공고의 정정·마감·취소 | 최신 상태·정정 근거 표시. 활성 청약처럼 안내하지 않음 | 미실행 |
| M16 | 목록 → 상세 → 원문 → 앱 복귀 → 뒤로 | 상세와 이전 목록 위치·초점 복원, 원문 외부 이동 안내 | 미실행 |
| M17 | 최대 지원 글자 크기, 화면 읽기만 사용 | 입력·오류 수정·모달·저장·삭제 도달 가능. 잘림·초점 갇힘·무명 버튼 없음 | 미실행 |
| M18 | 사용자 A가 B의 저장 ID로 조회·수정·삭제 요청 | 서버 권한 거부, B 데이터 노출·변경 없음. 앱 화면 검사로 대체 불가 | 미실행 |

M01~M17의 관련 과업을 iOS VoiceOver와 Android TalkBack에서 각각 기록한다. JSON 검증이나 스크린샷은 실기 접근성 통과 증거를 대신할 수 없다. M18은 서버 보안 검수 담당에게 인계한다.

## 6. 통합 전 결정 및 차단 조건

- 서버의 최종 작업 상태, revision 규칙, 취소 확정 의미, 재시도 단위가 JSON 계약에 명시되어야 한다.
- 공고 ID/모집 단위/회차/버전 및 정정·취소 관계가 안정적으로 연결되어야 한다.
- 개인정보가 포함될 수 있는 맞춤 입력을 오류·진행 알림·분석 이벤트·비로그인 영구 저장으로 넘기지 않도록 별도 검사한다.
- 실제 iOS/Android 시험 기기, 지원 OS·글자 크기 범위, 로그인 제공자가 아직 확정되지 않았다. 실기 테스트 전 실행 환경을 기록해야 한다.
- 이 문서의 완성과 합성 테스트 성공만으로 실제 출처 연동, 권한 검증 또는 시험 운영 완료를 선언할 수 없다.

인계: 총괄/서버는 위 의미와 JSON 계약의 대응을 검토하고 누락을 반영한다. 모바일 구현은 확정된 계약과 합성 응답으로 시작할 수 있으나 실제 출처 흐름의 완료 판정은 공식 응답·원문 대조 증거 및 두 운영체제 실기 기록 확보 후 수행한다.
